# UED Asset Hub V2.5.3 — 启动体验优化

日期：2026-10-23。版本演进：V2.5.2 → V2.5.3。

开发分支：`codex/v2.5.2-source-recovery`。上一版源码基线：`5244adc76346b93f90ac2f4fc612ce8abedba381`。

## 问题背景

原启动中心点击“启动”后会提前打开页面，并可能根据上一轮保留的 Hub 地址跳转；此时本次后端启动尚未完成，用户容易进入不可用页面。

## 本次优化

- 点击启动立即显示 Loading，文案为“正在启动，成功后自动跳转”。
- 请求进行中禁用重复启动及相关操作，并用同步请求标记阻止连续点击。
- 接收本次启动请求后，轮询现有受保护状态接口，等待操作完成。
- 仅在没有错误、服务归属状态有效且返回地址符合现有本机 HTTP / 已配置 HTTPS 边界时，在同一标签页自动进入 Hub。
- 启动失败、请求被拒绝或等待超时时保留启动中心，显示错误原因；旧地址不再触发提前跳转。

## 技术说明与文件范围

复用现有启动与健康检查机制，不新增独立服务，不改变正式数据结构、权限、安全检查、服务生命周期或存储路径。

- `scripts/competition-center-ui.tsx`：Loading、请求防重、等待结果及跳转逻辑。
- `scripts/verify-competition-center-startup-ui.mjs`：不使用服务或业务数据的内存定向回归。
- `delivery/competition/center/center.js`、`manifest.json`：现有生成脚本产出的对应离线资源及输入/输出摘要。
- 本变更说明。

`center.css`、`center.js.LEGAL.txt` 没有变化。生成资源在上轮实现时使用现有脚本及已有依赖生成，68 个参与包的版本与锁文件核对一致；本轮复用已验收资源，没有重复构建。
