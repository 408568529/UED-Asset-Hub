# Native Artifact Contract v1

Release-native helper builds require explicit `--mode release-native --staging-root --output-dir --temp-dir`. Output is limited to an ownership-proven staging candidate and compiler intermediates to the native build temp root. The Git checkout is never a release-native output location.

Each helper manifest is canonical UTF-8 JSON with a trailing LF. Historical local gate schema v1 remains readable; new release-native capture uses local gate v2 with actual argv fingerprint and PE inspection. It retains `version`, `architecture`, and `sha256` for existing consumers; `sha256` equals `binary.sha256`. The manifest records the Asset Hub commit, source and build-script hashes, toolchain identity, build-command fingerprint, PE/import facts, and explicit passed/deferred component checks. Unknown fields, unsorted string arrays, non-x64 identity, or a binary-hash mismatch are rejected.

The frozen set has exactly six digest members and uses `ued-asset-hub-native-set-v1`: the executable and integrity manifest for each of `job-helper`, `pipe-security-adapter`, and `dpapi-helper`. Historical `native-components.manifest.json` schema v1/v2 sets remain verifiable with their original `nb1`/`nb2` directory IDs. New sets use manifest and artifact-set schema v3. Their `nb3` ID is SHA-256 over canonical JSON containing schema version, source commit, source archive SHA-256, native source identity, toolchain identity, and build configuration. This separates identical native inputs built with the same toolchain when they belong to different frozen source archives. The v3 manifest binds the six hashes and sizes to the same authority fields and declared native source inputs; it remains assembly metadata, excluded from its own digest and from the later Release canonical payload. A run-specific sidecar binds the native set manifest to exactly one formal run ID, source commit, and archive SHA-256; it is required before constructor assembly.

Candidate promotion first verifies the exact set, all component-to-aggregate bindings, hashes, and the derived ID; it then uses a same-volume rename to the deterministic frozen directory. Repeating an identical promotion is idempotent. Release assembly copies only the six verified members and verifies every copied hash.

Windows-native reparse, hardlink, and ADS validation is performed only by `scripts/verify-windows-native-artifact-filesystem.ps1` against an approved staging path. Cross-platform contract fixtures do not claim that evidence.

For a new manifest-v3 set, the consuming Constructor also recomputes the source input list from its frozen source and rechecks every component manifest's fixed source/build-script path and hash, role recipe fingerprint, source commit, configuration, and declared compiler/linker/SDK versions. This leaves the v1/v2 schemas and the v1 digest member set unchanged.

`scripts/native-build-authority.mjs` validates NativeBuildReceipt v1; `native-build-capture.mjs` is called by all three release-native builders and records actual compiler/linker executable hashes/versions, SDK Include/Lib inventories, controlled tool environment, normalized argv, frozen Source inputs, output/PE/import facts, original creator and external observations/logs. Unknown runtime DLLs and unsupported delay imports fail closed. `create-native-build-receipt-set.mjs` independently validates and aggregates three original receipts; Approval and Constructor consumers recheck the selected raw set, actual members, aggregate and frozen Source inputs. Creator identity remains separate from current consumption Run.

Actual MSVC invocation, NTFS file-system validation and the protected Approval/permission integration must pass on the approved Windows host. Synthetic fixtures establish code contracts only. This implementation authorization does not permit creating V5 Native authority, promoting a set, constructing a Candidate or running Formal R3.
